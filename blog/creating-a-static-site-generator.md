# Creating a Static Site Generator From Scratch with Odin

A couple of weeks ago, I was looking through my YouTube subscriptions when I stumbled across [this](https://youtu.be/YvnTsiIFXeI?si=_NmHZcEHW9vMFekY) video by Ginger Bill, the creator of the Odin programming language, where he talks about how he made a static site generator for his blog with Odin. I had been considering making a blog for a while, and when I saw this video I decided, *why not?*

I've been learning Odin for the past month-or-so now, and I enjoy it quite alot. One feature that I love about the language is it's built-in vendor libraries. There are dozens of officially supported bindings in this library, including ones for Raylib, all the mainsteam graphics API's, and, most importantly for our purposes, Commonmark (a markdown rendering standard and library). So, I decided that I would follow in Mr. Bill's footsteps and create a static site generator with Odin and Commonmark (but in my case, it took *much* more than 6 hours because I'm an ameteur).

## File Structure

I pretty quickly decided on a structure for the project. It is a simple static site, so nothing robust is needed. We need the following to make a basic blog website:
1. A homepage
2. An index from which to access articles
3. A subdirectory containing the actual articles
4. An about page/bio

The file structure for this website is as follows:

```
index.html
about.html
articles.html
blog
  /article.md
  /article.html (generated by our program)
(code and assets are stored "loose" in the root directory. 
No need to further organize them right now)
```

## The Code

Now let's dive into the code.

While coding the basics I defined a couple of structs to implement useful features. First, I made a `blogEntry` struct that we will use to store metadata later
```
date :: struct {
	day, month, year: int
}

blogEntry :: struct
{
	url: string,
	title: string,
	date: date
}
```

I also created a struct that simply stores two strings. We can use this to easily enclose html data in its parent tags, ex. wrapping an article in the website's header and footer. I decided to call it a sandwich, because how could I pass up that opportunity?

```
sandwich :: struct
{
	top, bottom: string
}

fillSandwich :: proc(s: sandwich, filling: string) -> string
{
	return strings.concatenate({ s.top, filling, s.bottom });
}
```

### Creating a Custom Preprocessor
Most static site generators handle metadata using a custom Json or YAML tag at the start of each article file. I like the convenience of this solution, but I also want full control over how my metadata is formatted, and I don't want to deal with parsing Json when it's not necessary. So I defined a simple config tag that you can see at the top of the markdown source for this article. Writing the preprocessor that parses out the data wasn't too much of a hassle, and I was able to clean up the code into something I'm content with for now.

```
builder:= strings.builder_make();

	mode:= preprocessorMode.COPYING;
	it := string(data)

	for line in strings.split_lines_iterator(&it) {
		trimmed := strings.trim_space(line)

		if trimmed == "{START_CONFIG}"
		{ mode = .SCANNING; continue; }
		else if trimmed == "{END_CONFIG}"
		{ mode = .COPYING; continue; }

		switch mode {
		case .SCANNING:
			switch trimmed {
	   			case "TITLE":
				{ mode = .TITLE; continue }
	      		case "DATE":
				{ mode = .DATE; continue }
      		}
		case .COPYING:
			strings.write_string(&builder, strings.concatenate({line, "\n"}))
		case .TITLE:
			entryData.title = line;
			fmt.printfln("Title: %s", entryData.title);
			mode = .SCANNING;
			continue;
		case .DATE:
			entryData.date = processDateFromString(line);
			fmt.printfln("Date: %d.%d.%d", entryData.date.day, entryData.date.month, entryData.date.year)

			mode = .SCANNING;
			continue;
		}
	}
```

### Rendering to html
After this, the rest isn't too difficult either. Just iterate through each .md file in the `blog` directory and process them with CMark.

```
parseMarkdownFile :: proc(data: []byte, dest: string)
{
	root := cm.parse_document(&data[0], len(data), cm.DEFAULT_OPTIONS)
	defer cm.node_free(root)

	html := cm.render_html(root, cm.DEFAULT_OPTIONS)
	defer cm.free(html)

	htmlStr:= fillSandwich(ARTICLE_BODY, string(html))
	htmlStr = strings.concatenate({ HEADER, htmlStr });
	htmlStr = fillSandwich(HEAD, htmlStr);

	raw := transmute([]u8)htmlStr;

	ok := os.write_entire_file(dest, raw);
}
```

## Creating a Style
The other half of the work on this project went into writing static html data like the header, footer, and html metadata, as well as creating a style-sheet from scratch. I'm not knowledgable about either except for some basics I still remember from several years ago, but thankfully html and css are very well documented.

If you happened to take a look at Mr. Bill's video, or the [blog](https://www.gingerbill.org/) that is the subject thereof, you probably immediately noticed the resemblence. This is largely because I really liked the font he used for his website, and so decided to download the same one and use it here. You can learn more about the ET Book font [here](https://edwardtufte.github.io/et-book/).

Other than that, I kept things simple, partially due to lack of skill, but more importantly because I prefer it that way. I quite enjoy the fusion between the soft blue colors typical of the modern web and the old print book aesthetic provided by the ET Book font.
